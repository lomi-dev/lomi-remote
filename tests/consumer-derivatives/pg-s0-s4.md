PostgreSQL. Root must review these sources and explicitly admit one execution
before running the command below. The appointment argument records that prior
decision; it does not authorize execution. The older eight preparation sources,
frozen fourteen-file candidate, pure constructor and original NULL pins stay
unchanged. Their older Windows/stream notes describe earlier appointments.

The driver writes a new UUID directory under `artifacts/consumer-derivatives-s0-s4`

## Empty ledger fixture for frozen permissions compatibility

The first actual SQL-only attempt stopped at S2 because the frozen permissions
script revokes access to `public._prisma_migrations`, normally created by the
Prisma engine. The failed controller `6c2d9f6d-d820-4dad-9a4c-e8b613f11552` and
fixture `fb406548-d918-411f-b98b-e0aee2a61800` remain immutable failure evidence.

The explicit new `pg-s0-s4-ledger-fixture.sql` creates the complete eight-column
PostgreSQL table shape documented in Prisma's official
[schema-engine architecture](https://github.com/prisma/prisma-engines/blob/main/schema-engine/ARCHITECTURE.md#the-_prisma_migrations-table).
This is empty fixture compatibility support for the unchanged frozen REVOKE.
It does not execute or qualify Prisma7.10, fabricate migration rows/checksums,
or claim that Prisma applied any migration. `prismaLedgerQualified` stays false.

In each of the three fresh databases the driver replays the same24 exact frozen
migration scripts, applies this identical named fixture exactly once, requires
its count to be0, then runs the six unchanged constructor-selected frozen ops
work items in their original order. CREATE has no IF NOT EXISTS fallback: an
existing table rejects the fixture. The driver checks count0 again before S4
catalog capture. The fixture hash appears in the driver closure, explicit
baseline schedule, executed SQL transcript and transition manifest. No frozen
migration/ops source, pure reference constructor or candidate pin is changed.

Psql now uses `-v VERBOSITY=verbose` for this schema-only driver so a future error
retains its actual SQLSTATE alongside the existing stop-on-error transcript.
This does not authorize future lifecycle/credential payloads. A new wrapper with
updated source pins must be reviewed and separately admitted before another run;
the previous wrapper remains unchanged and cannot admit the updated driver.


## Trigger WHEN capture after the observed S2 SQLSTATE22023

Attempt `d92e5638-152d-466f-b163-cbb278c3342c` stopped in S2 metadata capture:
`pg_get_expr(tgqual,tgrelid,false)` rejected a trigger WHEN expression involving
OLD and NEW. Its executed proof and fixture `c726e422-3f25-4d7c-b7e1-33ecdfd700a6`
remain immutable failure evidence. No candidate installation was attempted.

PostgreSQL18's official [system information function documentation](https://www.postgresql.org/docs/18/functions-info.html#FUNCTIONS-INFO-CATALOG-TABLE)
documents `pg_get_triggerdef` as reconstructing the complete trigger command and
`pg_get_expr` in terms of one relation's expression Vars. The new capture retains
`definition=pg_get_triggerdef(oid,false)` unchanged and records
`whenTriggerDefinition=CASE WHEN tgqual IS NULL THEN NULL ELSE pg_get_triggerdef(oid,false) END`.
It no longer asks the single-relation expression deparser to render trigger
OLD/NEW references. There is no regex extraction, raw node-tree rewriting, or
function/ACL normalization.

Ordinary trigger comparison preserves the complete definition, including WHEN.
Internal triggers without WHEN retain the existing explicit semantic comparison
for generated names. If an internal trigger has a non-NULL WHEN, the complete
`whenTriggerDefinition` is compared strictly, including its generated name; a
cross-database difference rejects conservatively. Missing/present or changed
WHEN, full ordinary definition, enabled/deferral state and other semantic fields
all remain comparison differences. Raw captured rows are never modified.
