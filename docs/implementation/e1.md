# E1 local product host

The first product implementation is in `crates/lomi-host`, `lomi-host-store`,
`lomi-platform`, `lomi-terminal` and `lomiremote`. These crates are separate from
the E0 spike executables. They use the canonical Rust protocol and terminal
engine. Existing desktop, identity, web and mobile checkouts remain unchanged.

`lomiremote daemon run` owns a private profile, a lifetime native lock and an
OS-authenticated Unix socket. Detached startup verifies IPC readiness; shutdown
uses authenticated IPC and waits for the owned runtime to release its endpoint.
The process has no Tauri, WebView or Node runtime dependency. `status`, `doctor`
and workspace commands use the same local API as the Ratatui dashboard. A bare
invocation requires both stdin and stdout to be terminals. Closing the dashboard
restores terminal modes and leaves the host running.

SQLite stores host/profile identity, workspace context, terminal descriptors,
consent, fences, minimal receipts and bounded event/publication journals. A
local unshare commits its fence before returning, including at journal capacity.
One-use external-operation permits do not turn SQLite into an OS transaction:
uncertain effects become `outcome_unknown` and are never automatically repeated.
The PTY service alone parses output and produces snapshots, including while no
view is attached. Control belongs to a live authenticated connection; input
receipts are bounded RAM records rather than a persisted transcript.

Useful focused checks:

```sh
cargo test --locked -p lomi-host-store
cargo test --locked -p lomi-platform
cargo test --locked -p lomi-terminal
cargo test --locked -p lomiremote
```

The live PTY check exercises foreground Ctrl-C, local view exit, terminal-mode
restoration and observing output produced after that exit.
